### #1 K-1 — Liquidation-reserve remainder is refunded to a defaulting trader when a SHORT price loss is written off
- **Verdict:** SURVIVE · rank score 62 · signing gate: `warn`
- **Impact class (Panther):** direct_user_fund_loss · actor: permissionless · known-issue overlap: 0.151 (< 0.3)
- **Locations:** libraries/CfdEnginePlanLib.sol:1521,1531; libraries/LiquidationAccountingLib.sol:66-74; MarginClearinghouse.sol:1279-1287
- **Why it survived:** survives all kill gates with a complete validation template; next gate is a runnable PoC (Layer 4)
- **Test coverage:** No test exercises the SHORT write-off path: TerminalPriceWriteoff.t.sol uses a LONG and only checks position removal.
- **Validation template (awarexone):**
  - **SETUP:** Inverse product, SHORT position open; price gaps down hard so price loss > pledge + claim; liquidation reserve was locked at open.
  - **CALL:** OrderRouter.executeLiquidation / executeLiquidationBatch -> CfdEngine.liquidatePosition -> settlement sidecar -> MarginClearinghouse.applyLiquidationSettlementPlan
  - **RESULT:** Defaulting trader withdraws (reserve - minBounty) as free settlement while LPs absorb the written-off price loss.
  - **COST:** Open the position and its margin; liquidation itself is permissionless and single-transaction.
  - **DETECT:** No guardian reaction is realistic: liquidation is permissionless and settles in one transaction; reactive pause cannot claw back an already-unlocked remainder.
  - **NET ROI:** Positive whenever reserve - minBounty > position opening costs; scales with reserve size.
